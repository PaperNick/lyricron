How Lyricron Decodes Audio in the Browser

A quick look under the hood: how a lyrics tool plays your audio without ever sending it anywhere, and why some files drift.

Sep 27, 2026 5 min read

The Web Audio API, in brief

When you drop a file in, Lyricron reads the raw bytes in memory and hands them to the browser's Web Audio API, which decodes them into an AudioBuffer of sample data. From that point on, playback is just the browser reading samples out of memory on a precise clock. The file never leaves the page.

Why the clock matters for timing

The Web Audio API exposes a high-resolution clock (AudioContext.currentTime) that's far more accurate than JavaScript's Date.now() or setTimeout. Lyricron stamps each lyric using that audio clock, which is how a tap gets turned into a millisecond-accurate timestamp rather than an approximate one. This is the difference between "roughly on beat" and "indistinguishable from a studio sync".

Where VBR drift comes from

Variable-bitrate (VBR) files store audio in uneven chunks, and some decoders report time in a way that doesn't map perfectly to real playback time. The result is the familiar "starts fine, drifts by the end" behavior. It isn't a bug in your lyrics, it's a property of the file. The fix is to nudge the affected lines or retime the drifting section, covered in how to fix out-of-sync lyrics.

Offline-first storage

Your in-progress project auto-saves to the browser's local storage, so a refresh doesn't cost you work. There's no server to sync to, no account to resume, and nothing stored anywhere but your own device. The tradeoff is that clearing your browser data clears the project, which is a feature if privacy is the point. The full rationale is in why your lyrics tool shouldn't need your song files.

A fallback for stubborn formats

If the browser can't decode a particular format natively, Lyricron falls back to a bundled decoder. The fallback runs in the same in-memory, on-device way as the native path, so the privacy model never changes. It's just there to widen the set of files you can throw at it.

The code is open source. If you want to see exactly how the decoding and timing work, the repository is on GitHub.
