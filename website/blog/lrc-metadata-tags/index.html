LRC Metadata Tags, Explained: [ar:], [ti:], [offset:] and Friends

The LRC format is mostly about timing lyrics, but it also carries a handful of optional metadata tags that describe the track. Here's what each one does and when it actually matters.

Sep 12, 2026 6 min read

What metadata tags exist

An LRC file is plain text. Lines that start with a tag in square brackets but no mm:ss time are metadata: they describe the file rather than time a lyric. The common ones are [ar:] (artist), [ti:] (title), [al:] (album), [by:] (creator of the LRC), [offset:] (a global time shift), and [length:] (song length). Every one of them is optional.

The identity tags: [ar:], [ti:], [al:], [by:]

These four are the "who made this" block, and they usually sit at the very top of the file:

metadata.lrc 
[ar:Artist Name]
[ti:Song Title]
[al:Album Name]
[by:Lyricron]
  • [ar:] is the artist. Some players show it as a fallback if the audio file's own tags are missing.
  • [ti:] is the song title, used the same way.
  • [al:] is the album name, mostly informational.
  • [by:] credits who wrote the LRC file, not the song. Think of it as the lyricist credit.

In practice, most players ignore these and read artist/title from the audio file's own ID3 tags instead. They matter most when you distribute an LRC file on its own, like on LRCLIB, where they're the only source of truth.

[offset:] and drift

The [offset:] tag shifts every timestamp in the file by a fixed amount, in milliseconds. A positive value means the lyrics are late relative to the audio and should be moved earlier, a negative value the opposite. It's a blunt instrument: it moves everything together, so it's only right when the whole file is off by the same amount.

That's exactly the "consistent drift" case, and it's what the shift-all feature in the how-to guide handles. For drift that grows through the song (usually a variable-bitrate file), a single offset won't fix it; you'll nudge individual lines instead.

[length:]

[length:] records the song's duration in the format mm:ss. A few players use it to pre-validate a lyrics file before loading it, but it's informational for most. If you include it, keep it accurate or leave it out entirely; a wrong value can make some players reject the file.

Which players honor them

Support is inconsistent, which is the honest answer to "should I include these tags?":

  • Musicolet reads [ar:] and [ti:] and honors [offset:].
  • foobar2000 honors [offset:] through its lyrics components.
  • VLC reads synced LRC but largely ignores metadata tags in favor of the file's own tags.
  • Poweramp reads the identity tags and applies [offset:].
  • LRCLIB and similar lyrics databases rely on [ar:] and [ti:] heavily.

We cover the player-specific behavior in more detail in the dedicated setup guides for Musicolet, VLC, foobar2000, and Poweramp.

When to use them

A short rule of thumb: include [ar:] and [ti:] if you're sharing the file with others, add [offset:] only when you know the whole file needs a uniform shift, and skip the rest unless a specific player you use wants them. For a file that just needs to light up the right line at the right time, the timestamps are what do the work; the tags are window dressing.
